# Task-4.2 — native Raiffeisen RBO/CAMT

The entrepreneur current-account backend includes connection management, an external-owner OAuth ceremony, an encrypted token vault, refresh rotation and account/daily statement reading through a native Go gateway. The allowlist covers legacy RBO accounts, camt.052/camt.053 report creation, report status/file and OAuth only. Payment routes and the browser collector are not used here.

Connections use household scope and shared command recovery. A generation change revokes secrets and jobs; a partner may request reauthentication but cannot receive the owner's OAuth URL or finish their callback. One-use state binds owner/session/connection/revision/generation for five minutes. Intent persists before code exchange; a lost response never repeats the exchange. Completed callbacks support readback. Signed ID tokens require previously confirmed issuer/JWKS, audience, nonce, subject, expiry, RS256 and an access hash when present. Incomplete configuration denies Code Flow. New `/oauth2` endpoints are not substituted for legacy endpoints.

Refresh and report requests persist a claim before external IO. Unknown outcomes are never retried automatically. An unresolved report blocks new report requests in that generation until operator reconciliation or fresh authorization. Refresh of an old revision is serialized; new tokens are encrypted with a new revision and immutable AAD. Provider/host admission, generation and lease are checked before IO and inside shared CommitPage. Revocation after reading retains evidence in quarantine without journal effects.

CAMT supports 1:N entry/details, exact amounts, RUR/RUB and separate Account UUID/accountKeys. Optional references register atomically. Fingerprint v1 excludes amount/time/report ID and does not depend on optional aliases. Empty remittance and `NOTPROVIDED` do not establish sufficient identity. Conflicting strong references of the same kind cause ambiguity even with an identical semantic hash; an absent alias or a newly appearing kind alone is not a conflict. The semantic hash excludes a new statement's raw digest; raw bytes remain evidence. A correction requires a previously stored strong reference and newer sourceAsOf. Matching parties/remittance without that proof remains source_ambiguous. CLBD supplies an owned observation; available/locked/debt/credit limit remain unknown without a confirmed mapping. OPBD is neither income nor a confirmed historical opening. Ambiguous FCHG does not automatically become a fee.

The native worker compares the current configured binding with the job binding before secret access; missing configuration denies IO. Unsupported bank assets remain in evidence with `unsupported_asset` without blocking independent supported accounts. Entry and detail currencies must match the account currency; `NOTPROVIDED` is excluded from references at both levels. Confirmed user-command refusals persist as terminal results, while infrastructure failures remain pending.

## Configuration before deployment

API and worker read `WANT_KEEP_JOB_BINDINGS_FILE` and `WANT_KEEP_CONNECTION_KEYRING`. Code Flow/refresh also require `WANT_KEEP_RAIF_CLIENT_ID_FILE`, private `WANT_KEEP_RAIF_CLIENT_SECRET_FILE`, confirmed `WANT_KEEP_RAIF_ISSUER` and local trusted `WANT_KEEP_RAIF_JWKS_FILE`. Redirect URI is fixed: `https://want-keep.tech/api/v1/connections/raiffeisen/callback`. Missing configuration safely denies authorization. A binding file describes builds but grants no admission. Separate provider and host checks must match the exact D-43 binding/admissionRevision.

`backend/cmd/raiffeisen-conformance` uses only an explicit private directory outside Git: `tokens.json`, `refresh-state.json` and a separate secret file. Directory permissions are 0700; files are 0600. `-refresh` explicitly permits one exchange; the durable marker remains pending after an unknown outcome. `-from/-to` creates one historical report and stores its ID for subsequent reading. Secrets, raw XML and personal account details never enter public fixtures, command results or logs. This CLI does not install tokens into a production vault.

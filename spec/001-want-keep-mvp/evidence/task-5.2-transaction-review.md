# task-5.2 — проверка операций и разрешённые команды

[English](task-5.2-transaction-review.en.md)

## Результат

Backend сохраняет ограниченный контракт `transaction_review_v1`, frozen projection и reference map, отдельные задания проверки сохранённых ответов, предложения, вопросы и версии ответов. Классификация использует активные категории/продавцов; распределение — сохранённые правила либо явный ответ участника. Связь проводится существующим matching только после подтверждения предложения. Подтверждённые связи по evidence продолжает обслуживать механизм task-2.4. Неизвестные комиссии, исходные суммы, даты, банковские статусы и защищённые значения не назначаются моделью.

Сохранённый provider outcome и `ai_validation` job атомарны. Серверная проверка повторяет права, revisions и защиту полей. Эффекты проходят через существующий журнал с аудированным решением, outbox и review requests. `no_change` и сохранение результата проверки не создают новые финансовые версии. Ошибочное/устаревшее предложение не оставляет частичного эффекта. Ответ свободным текстом сохраняет автора и отдельную answer revision; исходный оплаченный вызов не повторяется.

## Области изменений

- `ai/domain`, `ai/application`: ограниченные команды, reference checks, проверки ответа и ответы участников.
- `storage` и миграция 023: семейные связи, неизменяемые projections/validation receipts/answers и история переходов, восстановление saved outcomes, отдельные queues; миграции 001–022 не менялись.
- `delivery/review`, API/worker wiring и OpenAPI RU/EN: уточнения, предложения, session/Origin/CSRF, idempotency, безопасные ошибки, session-bound пагинация; детализация/история операций содержит состояние и ссылки.
- Runtime prompt/schema, offline suite, PostgreSQL/race suite, CI и каталог документации. Go/TypeScript контракты обновляются совместно.

## Проверка

Пройдены `make check` (включая воспроизводимость Go/TypeScript и документацию), offline `make eval-ai SUITE=transactions`, новая PostgreSQL suite `ai-commands` с race detection, integration suites `ai-budget`, `jobs`, `audit`, `matching`, `family-allocation`, `ledger`; для изменённых `ai-budget`/`jobs` также пройдён `-race`. Обязательная privacy suite пройдена через штатный `make test-integration AREA=privacy` с изолированным обработчиком документов. `git diff --check` пройден. Промежуточные отказы Unix socket и запуска privacy без обработчика устранены штатными окружениями и не выдаются за успешные проверки.

Проверенные сценарии новой suite: отдельный durable validation после provider outcome; классификация без второго движения; свободный ответ с отдельной job; malformed/money/injection boundary; stale revision; конкурирующие ответы и replay; семейная изоляция; сохранность ручной правки и rollback; HTTP/CSRF, 404, ограничения пагинации, повтор команды и завершение уточнения. Исходные денежные/lease/budget/privacy регрессии остаются отдельными проверками.

## Покрытие и ограничения

Доказательства относятся к backend-частям AC-012/018/019/021/022/060/064/069/078/081/085/086/090. Они не означают полную продуктовую приёмку этих AC. Каталоги/правила ограничены 100 элементами, кандидаты — 20; projection сообщает неполноту. Чековая классификация позиций, чат, бюджет/цели, доставка уведомлений и UI остаются профильным задачам. Применение бюджетного/целевого предложения без соответствующего обработчика возвращает `feature_unavailable`.

`gpt-5.6-terra`, xhigh и общий лимит $50 сохранены. Новая schema/prompt имеет новые fingerprints и проверяется offline; `production_admitted=false`. Исторический результат 206/206 не квалифицирует новый runtime. Реальный OpenAI IO, live provider qualification, Chrome/Arc и production не выполнялись. Статус SDD остаётся **Ready for development**; эксплуатационная готовность не подтверждается.

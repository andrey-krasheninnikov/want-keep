# task-5.3: чеки и позиции

[English](task-5.3-receipts.en.md)

## Результат

Backend связывает accepted attachment и выбранный семейный счёт с долговечной обработкой безопасных raster-страниц. Каждая страница проходит общий Responses gateway с лимитом расходов, отдельным контрактом `receipt_extraction_v1` и серверной проверкой сохранённого результата. Один чек создаёт один расход, требует уточнения, пропускается с причиной либо связывается с подтверждённой оплатой.

Позиции и скидки проверяются точной арифметикой шести активов. Неизвестные факты не превращаются в ноль; конфликтные страницы и mixed receipts не проводят деньги. Алиасы категорий ограничены сохранённым контекстом и актуальной active revision. Доли, matching, corrections, аудит и возвраты используют существующие сервисы. Повтор файла сохраняет авторов evidence без второго вызова. Дата без времени сохраняет точность `day`.

API: `POST /receipts`, `GET /receipts/{id}`, `POST /receipts/{id}/answers` и `POST /receipts/{id}/allocations`. Запись использует сессию, Origin/CSRF, Idempotency-Key и проверку revisions; неизвестный результат восстанавливается через `/commands/*`. Миграция 025 добавочная; 001–024 не меняются. Образы страниц не копируются в `ai_attempts.allowed_input`.

## Доказательства

Пройдены `make check` (форматирование, vet/lint, TypeScript, unit/tooling, сборки, RU/EN и воспроизводимость контрактов), integration suites `receipts`, `ai-budget`, `ai-commands`, `jobs`, `audit`, `matching`, `family-allocation`, `refunds`, `ledger`, `storage` и обязательная `privacy` через изолированный процессор. Пройдены race suites `receipts`, `ai-budget`, `jobs` и узкие race-тесты extraction-контракта. Поздние изменения декодера и OpenAPI проверены по затронутым unit/HTTP/typecheck-сценариям; неизменённые успешные проверки повторно не запускались. `git diff --check` пройден. Финальный CI здесь ещё не заявляется.

PostgreSQL suite `receipts` проверяет HTTP, точный round trip шести активов, скидку 600 + 400 − 100 = 900, два автора одного файла, replay/changed payload, чужие ресурсы, Origin, конкуренцию, rollback, уточнение и конфликт версии. Возможное совпадение подтверждается без второго расхода. Смешанные позиции дают A 400 / B 600; возврат совместных 200 сохраняет исходный месяц и 100 на каждого участника. Неизвестный provider outcome не повторяется. Offline suite проверяет строгую extraction-схему и отказ от лишних команд/полей.

Live-проверка использовала синтетические RU-фото, EN-фото с USDC 0.000001, PDF из двух страниц, меню и чек с вредоносной инструкцией. Все пять итоговых сценариев прошли через текущий gateway и PostgreSQL; PDF обрабатывался изолированным процессом без сети. Всего 9 generation-вызовов с учётом исправления тестового численного сравнения и поддержки промежуточной страницы. По сохранённому usage и закреплённым тарифам расход составил USD 0.070756 из разрешённых USD 2. При отсутствующем cache-write count применяется консервативная стоимость. Биллинг провайдера отдельно не сверялся; нерешённых live outcomes нет.

`make eval-ai SUITE=receipts MODE=live` запускается только при `WANT_KEEP_RECEIPTS_LIVE=1`, явных путях `WANT_KEEP_OPENAI_API_KEY_FILE`, `WANT_KEEP_RECEIPTS_LIVE_JOURNAL`, `WANT_KEEP_TEST_PROCESSOR_SOCKET` и изолированной тестовой PostgreSQL. Приватный журнал должен существовать заранее, иметь mode 0600 и первоначальное содержимое `[]`. Его нельзя пересоздавать между попытками: unresolved entry блокирует дальнейшие платные вызовы; резерв каждой новой попытки должен помещаться в оставшиеся USD 2. Ключ не входит в исходники, образы, аргументы или журнал расходов.

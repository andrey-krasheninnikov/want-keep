# Voice

Want speaks calmly and directly. Be friendly without being familiar. Use ordinary words, active verbs, and the amount of detail needed to make a decision. Follow the product's language and terminology; the examples below are patterns, not a localization dictionary.

## Actions and states

| Purpose | English | Russian |
| --- | --- | --- |
| Save | Save changes | Сохранить изменения |
| Download | Download PNG | Скачать PNG |
| Retry | Try again | Попробовать снова |
| Loading | Loading preview… | Загружаем превью… |
| Confirmed success | Changes saved | Изменения сохранены |
| Recoverable error | Could not load the preview. Try again. | Не удалось загрузить превью. Попробуйте снова. |
| Empty search | No matches. Try another query. | Ничего не найдено. Попробуйте другой запрос. |
| Destructive action | Delete file | Удалить файл |

Name the action rather than using vague labels such as "OK" or "Submit" when the action is known. Keep related controls grammatically consistent. Use one term for one concept within a product.

Use a short state title when scanning matters. Add a description only when it explains a consequence or a next step. Do not repeat the title in the description.

## Trust

- Report what happened. "Changes saved" follows confirmed persistence, not the initial click.
- Explain a known recovery action. Do not invent a cause, deadline, retry, or promise.
- State consequences before destructive actions. Preserve useful details such as the affected file, amount, or destination.
- Do not blame the user, use humor in failures, or make routine errors dramatic.
- Avoid unsupported superlatives and phrases such as "effortless", "revolutionary", "unlock your potential", or their translated equivalents.
- Keep necessary uncertainty and technical facts. Product names, file formats, identifiers, and accessibility labels remain precise.

Match the user's locale and the product's established form of address. Keep public component labels in the consumer so they can be translated and tested in context.
